What is here

Binary packages, built from tagged releases and signed on the repository host.

librenms-webterm-gw

The SSH gateway for the LibreNMS WebTerm plugin. It terminates the browser's WebSocket, dials SSH and verifies host keys. A single static Go binary: it holds no database credentials, no Vault token and no LibreNMS session, and it never calls back into LibreNMS.

Browse the trees

Plain directory indexes. The apt metadata is under deb/dists/stable/; the dnf metadata is under rpm/repodata/. Neither needs to be fetched by hand — the commands below do it.

/deb/ The apt repository: pool, dists, InRelease. /rpm/ The dnf repository: packages and repodata.

Add the repository

Run the block for your distribution, as a user with sudo. Both are tested.

Debian and Ubuntu

Debian / Ubuntu 
curl -fsSL https://packages.adaptivedatanetworks.com/adn-archive-keyring.asc \
  | sudo gpg --dearmor -o /usr/share/keyrings/adn-archive-keyring.gpg

sudo tee /etc/apt/sources.list.d/adn.sources >/dev/null <<'EOF'
Types: deb
URIs: https://packages.adaptivedatanetworks.com/deb
Suites: stable
Components: main
Architectures: amd64 arm64
Signed-By: /usr/share/keyrings/adn-archive-keyring.gpg
EOF

sudo apt update && sudo apt install librenms-webterm-gw

Signed-By scopes the key to this repository alone, which is the point; apt-key applied a key to every repository on the system and is gone from Debian 12 and Ubuntu 24.04. The --dearmor matters because the bytes must match the filename — armoured content in a file named .gpg fails with NO_PUBKEY, which reads like a signing problem and is a file-format one.

RHEL, Rocky and Alma

RHEL / Rocky / Alma 
sudo rpm --import https://packages.adaptivedatanetworks.com/adn-archive-keyring.asc

sudo tee /etc/yum.repos.d/adn.repo >/dev/null <<'EOF'
[adn]
name=Adaptive Data Networks
baseurl=https://packages.adaptivedatanetworks.com/rpm/
enabled=1
gpgcheck=1
repo_gpgcheck=1
gpgkey=https://packages.adaptivedatanetworks.com/adn-archive-keyring.asc
metadata_expire=300
EOF

sudo dnf install librenms-webterm-gw

gpgcheck=1 verifies each package's own signature; repo_gpgcheck=1 verifies the repository metadata that lists them. Both are on deliberately — the second is what stops someone substituting the index itself.

One repository, every platform

There is no $releasever and no $basearch in either URL, and that is not an oversight. The gateway is a static binary with no shared-library dependencies, so one repository serves EL 8, EL 9 and EL 10, every current Debian and Ubuntu release, on amd64 and arm64. One suite, stable; one component, main; both architectures in the same index.

The package deliberately does not start the gateway. One started before its allowed origins are set refuses every browser connection with a 403 and looks broken, so run librenms-webterm-setup once the package is installed.

The signing key

RSA 4096, valid until 2031-09-09. Everything in both repositories is signed with it.

Check the fingerprint before you trust the key. Fetching it over HTTPS proves only that you reached this host. Compare it against a second source — the project's SECURITY.md, linked below — before you import it.

Fingerprint 1880 C40E 19DC 890F 8F00 8D0C F729 7BB1 4290 D3DF

Check it yourself

Any host with gpg 
curl -fsSL https://packages.adaptivedatanetworks.com/adn-archive-keyring.asc | gpg --show-keys

It must print exactly this:

Expected output 
pub   rsa4096 2026-09-10 [SC] [expires: 2031-09-09]
      1880 C40E 19DC 890F 8F00  8D0C F729 7BB1 4290 D3DF
uid   Adaptive Data Networks Package Signing <packages@adaptivedatanetworks.com>

If it does not, stop: do not import the key and do not install anything. Report it through the project's security disclosure process instead.
